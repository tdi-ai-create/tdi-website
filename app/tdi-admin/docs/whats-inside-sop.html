What's Inside the Hub

The page we send a school before they sign anything. How to keep it true.

Live since 22 September 2026 at /for-schools/whats-inside

It exists so a district can see what is in the Hub without an account, and so sales has something to send that is not a login. Its real job is to survive being forwarded inside a district with two lines of context on top, so it has to stand alone with no meeting attached.

The one rule that governs everything here

Nothing appears on that page until a person puts it there. Publishing a Quick Win does not put it on the page, and it never will.

That is deliberate. Sorting by tags alone misfiles material: a welding heat input lab and a cosmetology lab card both sort into behavior because both carry a safety tag. On a page a superintendent is reading, that looks like carelessness.

The cost of the rule is silence. An item nobody assigns simply never appears, and the page looks complete either way. Everything below exists to break that silence.

When you check the site

Five minutes, in this order.

1

Does it load, and is the order right?

Behavior, instructional planning, paras, the first weeks, families, leading adults, teacher load, AI and technology. That order is a sales decision. Behavior opens because everyone recognises the problem, instructional planning is second because it is usually the initiative a district has already committed to, and teacher load sits near the end because retention is what you want a leader carrying into the call.

2

Read the four items at the top of each section.

This is the only part that sells. They fill themselves in by what teachers have actually opened recently, which keeps them current and occasionally leads a section with something you would not choose in a meeting. If you would not say it out loud to a superintendent, pin something else over it.

3

Open one accordion.

Skim for anything that does not belong in front of a buyer: internal material, half finished titles, anything trade specific enough to confuse rather than impress. Take it off the page rather than editing it.

4

Check the badges are not everywhere.

A few per section. If most items carry one, they have stopped meaning anything and something has gone wrong in the computation.

5

Press print once, on a tab you do not mind losing.

It opens the real print dialog and freezes that browser tab until you dismiss it. That is the dialog behaving normally, not a fault.

What updates itself, and what does not

A data change does not reach the page until the site is deployed

On 23 September the section a tool belonged to was corrected in the database, and the live page went on showing the old arrangement for more than half an hour, serving a cached copy every time. A deploy fixed it within a minute.

So assume nothing you change reaches a buyer on its own. Publish a tool, assign its section, move something between sections, then get the site deployed before you tell anyone to look.

What the page does work out for itself, at the moment it is generated: which tools sit in each section, which four show at rest, and every badge except Start here.

What never changes on its own: whether a new item appears at all, which section it lands in, your pins, the Start here badge, and the eight headlines with the sentence under each. Those headlines were approved on 22 September and live in app/for-schools/whats-inside/sections.ts. Changing that copy is a decision, not maintenance.

The alert that tells you something is missing

The daily Hub content health check names any Quick Win published in the last fortnight with no section, in the same email you already get when Hub content goes wrong. It reads like this:

6 Quick Wins published in the last 14 days have no hub_section, so they
are missing from /for-schools/whats-inside: Creative Ideas for Working
With Rigid Seating, Creative Ideas for Construction Paper ...

That is not noise, it is the page telling you it is falling behind. The first time it fired it caught six real tools that had been wrongly excluded.

It only looks back a fortnight on purpose. Around twenty older items are deliberately off the page, and an alert that fires forever is an alert everyone learns to ignore.

How to change what is on the page

Everything goes through the content sync API, which reads the row back after every write and refuses to report success unless it actually changed.

Put an item on the page

POST /api/hub/content-sync
{ "action": "set_section", "slug": "the-item-slug", "hub_section": "paras" }

The sections are exactly these, and a misspelling is refused with the list rather than quietly hiding the item:

ValueSection on the page
behaviorBehavior, and the minute it actually happens
instructional_planningPlanning that survives contact with a Tuesday
parasThe staff who get the least support
first_weeksThe first weeks, and every fresh start after
familiesTalking to families before it gets hard
leadingLeading and coaching adults
teacher_loadThe reason good teachers leave
ai_technologyAI, before it becomes a problem

Pin something to the top four

{ "action": "set_section", "slug": "the-item-slug",
  "hub_section": "paras", "hub_section_pin": 1 }

Lower numbers sort first. Two pins per section is the sensible limit. Pass "hub_section_pin": null to unpin and the item drops back into usage order.

Mark something as your recommendation

{ "action": "set_section", "slug": "the-item-slug", "hub_badge": "start_here" }

start_here is the only badge that can be set by hand, and it claims nothing about usage, so it is safe to put anywhere. Most used, Trending, Popular and New are computed and will be refused if you try to set them, because typing one of those in would be claiming a statistic nobody checked.

Take something off the page

{ "action": "set_section", "slug": "the-item-slug", "hub_section": null }

Add "dryRun": true to any of these to see what would change without changing it. For a course, pass "content_type": "course" and the course id.

The rhythm

Whenever something significant publishes. Set its section as part of QA. mark_reviewed accepts hub_section directly, so it is one field on a call that already happens rather than a separate job. It is not required yet, because requiring it would break the agent skills that do not send it, so for now the daily alert is the backstop.

Quarterly. Read the four at the top of each section and re-pin. Twenty minutes.

Every July. The real one. Before buying season, read the whole page as a superintendent would, check the seasonal sections still land, and refresh the pins for the year ahead.

Things that have already caught people out

Publishing is not appearing

Covered above, and it is the mistake this whole document exists to prevent.

status is not is_published

The Hub, and this page, read is_published only. The two disagree on more than half the library. Never judge what is live from status.

The first pass filed tools by the wrong rule

Sections were originally assigned by a rule that stopped at the first matching category, so the order of those checks decided everything. Calm Response Scripts, the most opened tool in the Hub, sat under the heading about why good teachers leave because it carries one stress tag. Corrected on 23 September by scoring every section and taking the strongest. If you ever re-derive the assignments, use scripts/whats-inside/score-sections.mjs, never the superseded SQL beside it.

Cover images are not usable

The stored thumbnails are generic icon art with broken characters along the bottom, reused across different tools. That is why this page shows no images at all. If covers are ever wanted here, they need generating from page one of each tool PDF first.

Deliberately absent, and it is not an oversight

No counts of anything. Not tools, not courses, not members, not views. Ordering and banding carry it.

Nothing opens a document. The page proves there is a lot. The meeting proves it is any good.

No community activity, and no named districts.

If you need to change the page itself

Code lives in app/for-schools/whats-inside/. Styling comes from app/for-schools/for-schools.css rather than a copy of it, so the palette and type cannot drift away from the sales page. The engineering copy of this document is docs/whats-inside-runbook.md; if the two disagree, fix both.
